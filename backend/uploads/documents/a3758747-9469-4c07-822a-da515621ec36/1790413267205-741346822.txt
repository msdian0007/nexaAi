Phase 3 — Step 5: Document Chunking

Step 5.1 — Decide our chunking strategy

For NexaAI, we'll initially use:

Chunk size:    1000 characters
Overlap:       200 characters

Example:

Document
────────────────────────────────────

Chunk 1
[ 1000 characters ]

       ← 200 character overlap →

Chunk 2
        [ 1000 characters ]

       ← 200 character overlap →

Chunk 3
                [ 1000 characters ]

The overlap helps preserve context between chunks.

Step 5.4 — Create chunking utility

Create:

src/document/document.chunker.ts

Add:

const CHUNK_SIZE = 1000;
const CHUNK_OVERLAP = 200;

export interface DocumentChunkData {
  content: string;
  chunkIndex: number;
}

export const chunkText = (
  text: string
): DocumentChunkData[] => {
  const cleanedText = text
    .replace(/\r\n/g, "\n")
    .replace(/\n{3,}/g, "\n\n")
    .trim();

  if (!cleanedText) {
    return [];
  }

  const chunks: DocumentChunkData[] = [];

  let start = 0;
  let chunkIndex = 0;

  while (start < cleanedText.length) {
    let end = start + CHUNK_SIZE;

    if (end < cleanedText.length) {
      const lastSpace = cleanedText.lastIndexOf(" ", end);

      if (lastSpace > start) {
        end = lastSpace;
      }
    }

    const content = cleanedText
      .slice(start, end)
      .trim();

    if (content) {
      chunks.push({
        content,
        chunkIndex,
      });

      chunkIndex++;
    }

    if (end >= cleanedText.length) {
      break;
    }

    start = end - CHUNK_OVERLAP;
  }

  return chunks;
};
Step 5.5 — Create chunk persistence service

Create:

src/document/document.chunk.service.ts

Add:

import { prisma } from "../lib/prisma";
import { chunkText } from "./document.chunker";

export const createDocumentChunks = async (
  documentId: string,
  extractedText: string
) => {
  const chunks = chunkText(extractedText);

  if (chunks.length === 0) {
    return [];
  }

  await prisma.documentChunk.deleteMany({
    where: {
      documentId,
    },
  });

  await prisma.documentChunk.createMany({
    data: chunks.map((chunk) => ({
      documentId,
      content: chunk.content,
      chunkIndex: chunk.chunkIndex,
    })),
  });

  return chunks;
};
Why deleteMany()?

Later, if a document is reprocessed, we don't want:

Chunk 1
Chunk 2
Chunk 3

Chunk 1
Chunk 2
Chunk 3

Instead, existing chunks are removed and recreated.

One important point

We're using character-based chunking for this first implementation.

Later, when we build the production-quality RAG pipeline, we can improve this with:

paragraph-aware splitting
heading-aware splitting
token-based chunk sizing
metadata per chunk
page numbers
document section information

For now, this implementation gives us a clean foundation for embeddings.
