# Phase 3 — Step 9.4: Answer-generation prompt

## What problem does the prompt solve?

Retrieval finds related text. It does not establish that the text answers the
question. The prompt gives a future language model a task: answer only from
the evidence, preserve conditions and exceptions, cite supporting excerpts,
and report missing or conflicting information instead of guessing.

## Separate rules from data

`src/rag/rag.prompt.ts` prepares two provider-neutral messages:

- `system`: fixed answering rules owned by the application.
- `user`: a JSON object containing `question` and `evidence`.

Only evidence source IDs and text are sent in the data message. Database IDs,
filenames, and similarity scores stay in the source mapping for later citation
resolution. A similarity score is not proof of factual correctness.

For example, the data message might contain:

```json
{
  "question": "How many vacation days do employees receive?",
  "evidence": [
    {
      "sourceId": "S1",
      "content": "Full-time employees receive 18 days of paid annual leave per calendar year."
    }
  ]
}
```

The requested answer format is a JSON object with `status`, `answer`, and
`citations`. This illustrative output has not been generated by a model:

```json
{
  "status": "answered",
  "answer": "Full-time employees receive 18 days of paid annual leave per calendar year. [S1]",
  "citations": ["S1"]
}
```

Keeping "full-time" and "per calendar year" avoids broadening the policy beyond
what the evidence supports. Inline citations attach evidence to a claim;
the citations array lets the application resolve source IDs to document records.

## Three outcomes

| Status | Meaning |
| --- | --- |
| answered | Evidence supports the requested answer |
| insufficient_information | Necessary details are missing, including partial answers |
| conflicting_evidence | Unresolved contradictions prevent a single supported answer |

For example, an annual leave passage does not establish a maternity leave
entitlement. A passage may be relevant without containing the required fact.
If two policies give different annual leave allowances, both should be cited
and the conflict explained. Search rank is not a rule for choosing which is true.

## Code behavior

`buildRagPrompt(question, context)` expects context built internally from
tenant-scoped retrieval. Do not accept a client-supplied context as evidence.
The function validates the question and ensures the evidence source IDs agree
with the citation mapping. It does not re-run tenant authorization.

If `hasContext` is false, it returns `shouldGenerate: false` plus an
insufficient-information response. There are no model messages. The future
generation service must honor this branch instead of making an API call.

Otherwise it returns `shouldGenerate: true`, the two messages, and a copy of
the source mapping. This is preparation only: no API call is made.

## Limits of this step

Requesting JSON is not enforcing a JSON schema. Types describe expected data
but do not validate a model's output. A later step must parse responses, check
fields and citation IDs, and handle provider errors. Even valid citations do
not prove that each claim follows from the cited text.

JSON encoding keeps embedded quotes or fake role declarations from changing
the message structure. It does not guarantee resistance to prompt injection.
The prompt tells the model to treat document instructions as untrusted text;
actual model behavior still needs evaluation with adversarial examples.

The 8,000-character context budget does not include the instructions, question,
serialization overhead of the full request, or generated answer. A provider's
token budget must be handled when integrating that provider.

## Preview and verify

From `backend`:

```powershell
npm.cmd run build
node scripts/preview-rag-prompt.cjs
node --test tests/rag.prompt.test.cjs tests/document.context.test.cjs
```

The preview uses one illustrative excerpt and needs neither a database nor an
API key. Tests verify message separation, source mapping, empty-context handling,
preservation of conflicting excerpts, and malformed-context rejection. They
do not demonstrate that a language model obeys the prompt.

The search endpoint is unchanged in this step. The prompt builder will be
connected to the answer-generation service in a later substep.
